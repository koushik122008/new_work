## 2024-05-14 - GC Pauses from Object Instantiation in Game Loops
**Learning:** Instantiating new objects (like `new THREE.Box3()`) inside high-frequency nested loops (such as collision detection in `updateProjectiles`) causes massive memory allocation overhead and leads to Garbage Collection (GC) pauses, which degrade the framerate in WebGL applications.
**Action:** Always declare reusable instance variables (e.g., `const sharedBox = new THREE.Box3()`) globally or outside the loop and mutate them inside the loop (e.g., `.setFromObject(...)`) to avoid frequent allocations.
## 2024-05-24 - [Three.js Object Pre-allocation in Game Loops]
**Learning:** In this Three.js codebase, dynamically instantiating geometries (e.g., `new THREE.CylinderGeometry`) and materials (e.g., `new THREE.MeshStandardMaterial`) inside high-frequency game loop functions like `spawnEnemy()` and `fireProjectile()` causes significant memory leaks and GPU resource exhaustion because Three.js does not automatically dispose of them, nor were they manually disposed.
**Action:** Always pre-allocate shared geometries and materials once during initialization (`init()`) and reuse those instances when creating new `THREE.Mesh` objects in the game loop to maintain optimal performance and prevent memory accumulation.
